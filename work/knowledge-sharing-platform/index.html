Knowledge-sharing platform

A multi-role editorial platform for publishing and peer-reviewing articles — built from a detailed specification covering roles, workflow, policies and dashboards.

Role: SoloStatus: Live

  • Next.js
  • TypeScript
  • Tailwind CSS
  • PostgreSQL + Prisma
  • Docker + nginx

Problem

Publishing articles with real editorial rigor — multiple reviewers, a copy-editing pass, scheduled publishing, audit trails, and policies that actually match what the app does — usually means stitching together a CMS, a spreadsheet for tracking who's doing what, and email for the rest. This platform puts the whole editorial lifecycle, from first draft to a publicly citable article, behind one system with the rules built in rather than enforced by habit.

What I built

An editorial workflow engine with five scoped roles (Author, Reviewer, Copy Editor, Editor, Super Admin), each with its own dashboard, built against a 72-item specification covering workflow rules, data model, notifications, policies and extra features. I audited the finished build against that specification item by item: 97% complete (68 of 72 items done outright, 3 partially automated, 1 deliberately deferred), verified with unit tests, API and page-rendering checks against a real database for every role and rule, and a production build.

Key features

  • A strict state machine across the full lifecycle — submission, peer review, revision, copy-edit, final approval — with a permissions matrix enforced on every action, not just in the UI
  • Structured peer review: reviewers recommend, the editor decides, and a revision loop requires a written response to every round of comments
  • Copy-editing stage with SEO fields, DOI and citation IDs (allocated under a database lock, so none collide), and tracked text changes via versions
  • Scheduled and automatic publishing, with a background worker that publishes due articles every minute
  • Published articles are never overwritten — an edit becomes a new version pending editor approval, while the live article stays up the whole time
  • A full audit log of every status change, including editorial overrides recorded with a written reason, plus PDF export, public search/filtering, and SEO (sitemap, meta tags, canonical links)

The hardest part

Keeping "published" meaningful. Articles can't be silently edited once they're live, but editors still need to fix things — so an update to a published article becomes a new version that sits pending until an editor approves it, and the original stays visible and citable the entire time. Getting that right, alongside a strict per-role permissions matrix and a full audit trail of every status change, meant the state machine had to be airtight: no action that bypasses a rule, no status that isn't logged.

Result

97% complete against a 72-item specification, independently audited section by section (workflow rules, data model, notifications, IDs and business rules, policies, submission form, and dashboards all at 88–100%). The 3 remaining partial items are intentional product calls, not bugs: editor assignment falls back to manual claiming only when a division has no editor (and super admins are notified so nothing is orphaned), a copy-edit guardrail is enforced by notification rather than a hard block, and engagement analytics beyond anonymous view/download counts were deliberately left out to avoid cookies and trackers. The one missing item — payments for sponsored content — needs a business decision and a merchant account before it's worth building.
